# Focus Desktop: план реализации

Небольшая утилита для Windows 11. Скрывает иконки рабочего стола одной кнопкой, чтобы не отвлекаться во время работы.

## 1. Цель

- Плавающая кнопка поверх всех окон на главном мониторе. Её можно перетащить в любое место.
- Клик по кнопке переключает видимость иконок рабочего стола.
- Иконка в трее. Левый клик переключает иконки. Правый клик открывает меню.
- Выход из программы убирает кнопку и иконку из трея и возвращает иконки на рабочий стол.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Где кнопка | Только на главном мониторе |
| Поверх чего | Поверх всех окон, включая полноэкранные приложения |
| Левый клик по трею | Переключает иконки: показать → скрыть → показать... |
| Правый клик по трею | Меню |
| Горячая клавиша | Не нужна |
| Автоматическое скрытие при фокусе на приложении | Не нужно. Только ручное переключение |

## 3. Функциональные требования

### 3.1 Плавающая кнопка
- Окно без рамки и заголовка, поверх всех окон.
- Не показывается в Alt+Tab и на панели задач.
- Перетаскивание мышью: зажал ЛКМ и двигаешь.
- При первом запуске появляется в правом верхнем углу главного монитора.
- Позиция сохраняется между запусками.
- Если сохранённая позиция вне экрана (например, сменилось разрешение), кнопка переносится в видимую область.
- Внешний вид показывает текущее состояние: например, другой значок или цвет, когда иконки скрыты.

### 3.2 Переключение иконок
- Клик по кнопке и левый клик по трею делают одно и то же.
- Состояние не хранится в переменной. Каждый раз проверяется реальная видимость окна иконок. Так программа не рассинхронизируется, если иконки переключили правым кликом по рабочему столу или Win+D.

### 3.3 Иконка в трее
- Обычная иконка в области уведомлений.
- Левый клик: переключить иконки.
- Правый клик: меню:
  - «Скрыть иконки» / «Показать иконки» (текст зависит от состояния);
  - «Показать/спрятать кнопку»;
  - «Автозапуск с Windows» (этап 4, по желанию);
  - «Выйти».

### 3.4 Выход
- Убирает кнопку с экрана.
- Удаляет иконку из трея.
- Возвращает иконки рабочего стола, если они были скрыты.
- Процесс полностью завершается и не остаётся в диспетчере задач.

## 4. Технический подход

### 4.1 Стек
- **Прототип:** AutoHotkey v2. Быстрый путь, чтобы проверить работоспособность.
- **Рабочая версия (по желанию):** Python (ctypes + pystray или PyQt) или C# (WinForms/WPF). Выбирается после прототипа.

### 4.2 Скрытие иконок рабочего стола
1. Найти окно `Progman`, внутри него `SHELLDLL_DefView`, затем `SysListView32`.
2. Если нужного окна нет в Progman, проверить окна `WorkerW`. Windows создаёт их при смене обоев и при Win+D.
3. Видимость: `IsWindowVisible(listview)`.
4. Скрыть: `ShowWindow(listview, SW_HIDE)`. Показать: `ShowWindow(listview, SW_SHOW)`.
5. Для сверки: правый клик по рабочему столу → Вид → Показывать значки рабочего стола. Это тот же эффект через `WM_COMMAND` 0x7402.

### 4.3 Перетаскивание кнопки
- AutoHotkey: `PostMessage(0xA1, 2, 0)` (имитация захвата заголовка) или обработка `WM_LBUTTONDOWN` с пересчётом позиции окна.
- Другие стеки: стандартный механизм перетаскивания окна без рамки.

### 4.4 DPI и монитор
- Включить DPI-awareness. Иначе на масштабе 125% и 150% кнопка окажется не там, где ожидается.
- Позицию хранить относительно главного монитора, а не в абсолютных пикселях.

### 4.5 Настройки
- Файл `settings.ini` или `settings.json`, в `%APPDATA%\FocusDesktop\`.
- Поля: позиция кнопки, размер, автозапуск.

## 5. Этапы

### Этап 1. Прототип (AutoHotkey v2)
- [ ] Кнопка без рамки, поверх всех окон, без Alt+Tab.
- [ ] Клик переключает иконки рабочего стола.
- [ ] Состояние определяется по реальной видимости окна.

### Этап 2. Перетаскивание и позиция
- [ ] Перетаскивание кнопки мышью.
- [ ] Сохранение позиции в файл настроек.
- [ ] Восстановление позиции при запуске.
- [ ] Защита от позиции вне экрана.

### Этап 3. Трей и меню
- [ ] Иконка в трее.
- [ ] Левый клик переключает иконки.
- [ ] Правый клик: меню со всеми пунктами из 3.3.
- [ ] Текст пункта меню зависит от состояния.
- [ ] Выход: возврат иконок, удаление кнопки и иконки из трея, полное завершение.

### Этап 4. По желанию
- [ ] Автозапуск с Windows (через папку Startup или ярлык).

### Этап 5. По желанию
- [ ] Переписать на Python или C#, если прототип понравился и нужен установщик.

## 6. Тестирование

- [ ] Кнопка перетаскивается и после перезапуска стоит на месте.
- [ ] Масштаб 100%, 125%, 150%: кнопка на месте и кликается.
- [ ] Два монитора: кнопка на главном, после отключения второго монитора не теряется.
- [ ] Иконки скрываются и возвращаются кнопкой и левым кликом по трею.
- [ ] Рассинхронизации нет: если иконки переключили через правый клик по рабочему столу или Win+D, кнопка и меню показывают правильное состояние.
- [ ] Поверх полноэкранного приложения кнопка видна.
- [ ] Выход возвращает иконки и убирает кнопку и иконку из трея.
- [ ] Перезапуск `explorer.exe` не ломает программу.
- [ ] Работа без прав администратора.

## 7. Риски

- Поведение `Progman` и `WorkerW` может отличаться в разных сборках Windows 11. Проверить на нескольких сборках перед релизом.
- Антивирусы иногда помечают скрипты AutoHotkey. Для рабочей версии лучше собрать exe или использовать Python или C#.
- Если программа упала, пока иконки скрыты, при следующем запуске их надо вернуть.
